# 거북선 이미지 생성

183장의 앵커 이미지(K)와 132개의 클립(V)을 만들어 `E:\YouTube\국뽕\1.이순신`에 저장한다.
프롬프트는 **절대 직접 짓지 않는다.** 저장소의 도구에서 받아온다.

## 시작할 때 항상 이것부터

```bash
python3 -m src.cli verify --kind image      # 어디까지 됐나
python3 -m src.cli next --kind image -n 5   # 다음에 만들 것
```

`next`는 저장 폴더에 실제로 있는 파일을 기준으로 판단한다. 별도 진행 기록을 만들지 말 것 —
어긋난다. 폴더가 곧 진행 상황이다.

## 구조

```
블록 1~14     서사 단락. 블록마다 내용도 조명도 다르다
 └ 비트 B1~B5  블록 안의 장소
    └ 컷 K1~K5 같은 장면을 카메라만 좁혀가며 뽑은 연속 컷
       └ 클립 V 컷과 컷 사이를 잇는 영상
```

파일명: `1블-b1-k1.png` / 그 사이 영상은 `1블-b1-v1.mp4`.

## 규칙 1 — K1은 새 생성, K2부터는 같은 스레드에서 편집

이게 가장 많이 틀리는 부분이다.

- **K1** — 반드시 **새 이미지 생성** 창에서 시작한다.
- **K2~KN** — K1이 만들어진 **같은 스레드 안에서 편집(remix)** 으로 이어간다.
  카메라를 점점 좁히는 연속 컷이므로 같은 계보에서 나와야 한다.

**비트가 바뀌면 다시 새 생성으로 돌아간다.** b1이 끝나고 b2로 넘어갈 때
b1의 편집 창에 b2 프롬프트를 넣으면 안 된다. 장소가 다르다.

한 번 이 구분을 놓쳐서 전투 장면 편집 창에 자료실 프롬프트를 계속 넣은 적이 있다.
생성은 되는데 전부 엉뚱한 그림이 나온다. **매번 지금 어느 창에 있는지 확인할 것.**

## 규칙 2 — 블록마다 내용이 다르다

14개 블록은 각각 다른 장면이다. 내레이터 클로즈업, 사료 도해, 백병전, 공학 비교 실험,
충돌 장면, 지도 분석… 한 블록의 장면 묶음을 다른 블록에 돌려쓰면 안 된다.

이 실수로 2블록 11장을 통째로 폐기한 적이 있다. 내레이터 클로즈업이어야 할 자리에
1블록과 똑같은 해전 장면이 나왔다.

**방지책은 하나다: 프롬프트를 `next`나 `show`에서 받아 그대로 쓴다.**
기억해서 쓰거나 요약해서 쓰지 않는다.

```bash
python3 -m src.cli show 2블-b1-k4
```

## 규칙 3 — 시드 고정

`1블-b1-k1`을 먼저 뽑아 마음에 드는 결과의 시드를 확보한다.
이후 모든 프롬프트의 `[SEED]` 자리에 같은 값을 넣는다. 183장의 그림체를 묶는 유일한 장치다.

`next`가 내주는 기본 모드(`natural`)는 나노바나나 프로용이라 `[CAST]` 같은 자리표시자가
이미 펼쳐져 있다. 미드저니 문법이 필요하면 `--mode mj`.

## 생성 설정

16:9 · 1장 생성. 다른 비율이나 여러 장은 쓰지 않는다.

## 저장

생성 직후 **바로 위에 적힌 이름 그대로** `E:\YouTube\국뽕\1.이순신`에 저장한다.
나중에 몰아서 이름을 붙이지 않는다 — 순서가 섞이면 복구가 어렵다.

한 비트(3~6장)를 끝낼 때마다 `verify`로 실제로 들어갔는지 확인한다.

## 한도에 걸렸을 때

Flow 크레딧이나 사용량 한도 메시지가 뜨면:

1. **재시도를 반복하지 않는다.** 5분 간격으로 여러 번 시도해도 안 되면 계정 한도다.
2. 지금까지 완료된 것을 `verify`로 집계해 보고한다.
3. 멈춘 지점(`next`가 가리키는 파일명)을 알린다.
4. 결제나 플랜 변경은 사용자가 직접 해야 한다. 대신 처리하려 하지 않는다.
5. 로그인도 마찬가지다. 비밀번호를 대신 입력하지 않는다.

한도가 풀린 뒤에는 `next`가 알아서 정확한 지점을 짚어준다.

## 2단계 — 영상

이미지 183장이 **전부** 끝난 뒤에 Flow Omni로 넘어간다.

```bash
python3 -m src.cli verify --kind image     # 183/183 인지 먼저 확인
python3 -m src.cli next --kind video -n 5
```

클립 하나는 두 장을 넣어 잇는다: `1블-b1-v1`은 `1블-b1-k1` → `1블-b1-k2`.
각 10초.

## 블록을 추가할 때

`spec/isunsin.json`의 `blocks`에 한 줄 넣고 `python3 -m src.cli build`.

```json
{ "no": 15, "title": "...", "light": "B", "seconds": 70, "tempo": "중간",
  "anchors": 12, "clips": 9, "beats": [["B1",4],["B2",4],["B3",4]] }
```

`anchors`와 `clips`는 원문 헤더 값을 그대로 적는다. 검증용이다 —
`앵커 합 − 비트 개수 == 클립 합`이 어긋나면 로드가 실패한다.
컷수를 잘못 적어 수백 장을 버리는 일을 여기서 막는다.
